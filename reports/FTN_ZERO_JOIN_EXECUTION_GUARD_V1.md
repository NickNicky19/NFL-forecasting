## Guards and limits

- Required exact pinned external invocation: GNU timeout `--signal=KILL 60s`,
  base venv Python `-B`, frozen runner, freeze path and SHA256. The runner checks
  its timeout parent binary and argv. The timeout process is included in samples.
- Linux PDEATHSIG SIGKILL kills the worker if the supervisor dies, with a
  parent-PID race check. Worker Python audit hooks reject socket events and
  process creation. These controls protect this reviewed local helper; they are
  not claimed to sandbox arbitrary hostile native code.
- All five numerical-thread environment variables are one; existing PyArrow
  calls also set one CPU/IO thread and disable scan parallelism.
- Worker wall alarm 50s, supervisor worker-stop 53s, combined CPU stop 54s,
  supervisor alarm 59s, external wall kill 60s. Per-process CPU limits are
  additional backstops. There is no RLIMIT_AS setting.
- Every 10ms the supervisor samples timeout/supervisor/live-descendant RSS and
  CPU, adding reaped worker CPU. RSS stops at 240MiB, reserving 16MiB below the
  256MiB budget. Sampling can miss transient peaks. Child `ru_maxrss` is an
  individual-process observation, not a combined-tree peak guarantee.
- Stdout/stderr are drained concurrently and retained at at most 8192 bytes
  each; discarded byte counts are retained. Worker cleanup kills and reaps the
  child on monitor errors; no unbounded communicate/poll is used.
- The unchanged shared 512MiB quota, CAS ownership, and flock remain enforced.
  A wrapper adds stricter attempted-allocation ceilings: 3,932,160 worker
  payload bytes, 131,072 supervisor payload bytes, and 65,536 control/ownership
  bytes per process. Their sum is 4,194,304 bytes. Charges precede original
  writers and include attempts that fail, so abandoned CAS writes and repeated
  bodies do not escape the per-job reserve. The storage implementation itself
  and its existing checks remain unchanged.
- Code, config, Python binary, declared package versions, and source policy are
  authenticated before decoding and before successful completion. The unchanged
  helper authenticates owned input references on entry and exit.

The final receipt records usage before its own write. The tool observation after
that write is reported separately; neither is described as an unseen exact
process-exit measurement. A killed process may retain a consumption receipt
without a final receipt; that is a failed consumed attempt, not permission to
retry or a successful source qualification.
