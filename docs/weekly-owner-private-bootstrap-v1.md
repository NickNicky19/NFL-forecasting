## Packaging, upload and safe hosted handoff

Opaque file bytes stream in48KiB blocks into deterministic gzip JSON-base64.
No model, target or forecast JSON content is interpreted. The producer keeps
one capped8MiB compressed buffer and small working blocks, not an inflated26MiB
copy or a persistent payload duplicate. Limits: 64 files/bundle, 12MiB inflated,
8MiB asset, 32MiB runtime and 128 assets. Fixed conservative grouping leaves
compression overhead room. Runtime verifies actual sizes/hashes; no cap grows.
Only fictionals have been grouped/encoded; actual bundle hashes remain unrun.

The private root manifest is itself uploaded once as a digest-bound metadata
asset. A locator descriptor contains only release/canary IDs, hashes, sizes and
explicit owner origin, never private source paths. Future invocations may
read back an already completed exact root-metadata asset, without repeating its
POST. Each payload/entry is append-only. Every POST has a0600 O_EXCL reservation
before transport; a consuming per-bundle operation marker prohibits re-entry.
All unknown assets, orphans and pending reservations count. Ambiguous failures
remain evidence; there is no automatic retry/re-upload or deletion.

The existing core preserves default proxy/CA settings, finite requests and
known-CDN download redirects. Authorization/cookies never reach CDN/browser
hosts. Tokens, raw responses, signed URLs and bodies are never logged.

Genuine GHA restore requires an authenticated core Client/current job, fetches
the private root manifest via the safe locator, rechecks the actual owner comment
and original qualified run/jobs, then uses unchanged `read_asset`/`draft` for
exact remote bytes. Extraction verifies the closed logical whitelist, hashes,
sizes/base64 and original origins before existing owned CAS writes. Symlinks,
traversal, collisions and existing destinations fail. No archive filesystem
links or model deserialization occur. The old core restore schema is not relaxed.
