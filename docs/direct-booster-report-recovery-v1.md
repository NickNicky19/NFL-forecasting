# Direct booster frozen-row reporting continuation

This is a separately registered technical aggregation of the original direct
booster screen. Its terminal receipt remains FAILED. There are no new model
fits, predictions, forecast-law calls, source-label reads, or football data.
The twelve-category inventory retains 192 completed scored slots, six failed
XGBoost TD slots, and eighteen blocked exact-PPR slots.

The caller binds `config/direct-booster-report-recovery-v1.json` by exact SHA.
That file is maintained by the integrator. It binds the original execution,
forecast and scored freezes, FAILED terminal receipt, category/scoring contract,
control scored freeze and source policy. The output is a new private namespace
`direct-booster-report-recovery-v1-20261023`, under the existing global quota.

The run tool rejects unsealed execution freezes and requires independent
PREEXEC PASS. Every Python file in the original code assembly, all three new
tools, the plan and its metadata, and the full original environment file
inventory are bound by bytes, SHA256, inode and mode. The unchanged original
screen and direct-model modules have additional fixed SHA checks.

The prep-only builder accepts the exact integrator policy SHA256 and writes an
unsealed metadata template outside operational roots. It opens no parquet
values. `execution_metadata` holds the path/SHA/size bindings and original
resource warning; it does not modify the immutable policy file. The builder
itself is also frozen. All output goes through an additional 64 MiB prewrite
cap on newly retained content, retaining the original global quota checks.
Aliases of original CAS content do not consume new bytes. Execution metadata
and receipts already imported only in the new namespace do consume this cap.

At entry and exit the unchanged `owned_reference_batch` helper authenticates
all 192 immutable score files, 165 exact saved controls and four parent receipts
under the unchanged storage lock/CAS/quota checks. Count controls use the saved
CDF mean; signed targets use the original point semantics; TD uses the saved
probability. `target_report`, `subgroup_rows`, statistical uncertainty and
nomination rules are unchanged. Every completed target receives an immutable
private target report and a checkpoint before the next target begins.

The frozen outer supervisor uses one direct worker process, 0.1 second samples,
600 wall seconds, 600 CPU seconds, 2 GiB RSS and two numerical threads. Its
external command must also use `/usr/bin/timeout --signal=KILL --kill-after=1s
600s`. Inner stops reserve five seconds for terminal evidence. It retains peak
sampled and reaped CPU separately, taking their maximum for budget checking.
The supervisor verifies its actual parent is the pinned GNU timeout with the
exact frozen command. Before dependency checks, the worker arms Linux
`PR_SET_PDEATHSIG(SIGKILL)` and checks the expected parent PID before and after
arming. A final child `ru_maxrss` cross-check complements sampled combined RSS;
sampling can still miss brief simultaneous process peaks.

The original receipt's CPU field is not an exact complete-process total: the
original orphan runtime showed 1541.94 CPU seconds, while the reaped supervisor
chain showed 621.41 seconds. Their summed observed lower bound is 2163.35
seconds. The original receipt's 620.351459637 field is preserved verbatim.

These are exposed development observations. A successful reporting continuation
does not add NFL observations, restore failed forecasts, qualify a candidate,
prove a website gain, or activate/deploy a model.
