# Prospective consumer contract: next version, draft

Read-only design from `6b519dc`, October 23, 2026. **Not registered, implemented
or activated.** This specifies a concrete integration boundary for the existing
single workflow; it changes no frozen experiment or confirmation window.

## What exists

The workflow runs daily capture before its optional Sunday weekly probe.
`state.capture` retains the first `(player_id, game_id, target, model_id)` row.
Daily operational reference fits bind their exact training and query inputs;
weekly synthetic-query artifacts are not loaded by daily inference. The current
publication qualifier requires the original full scope envelope and rejects
duplicate opportunities across batches. Existing scorers remain legacy-inclusive.
These facts prevent claims of weekly learned-parameter reuse, registered refresh
horizons or qualified prospective scoring from software existence alone.

## Proposed collection identity

Use a new, explicit registration/policy version for operational references and
each later challenger. Keep policy identity separate from parameter-instance and
source/input hashes. Proposed primary collection horizon: game-day daily capture
in the existing 08:36–08:56 America/Chicago gate (`D0_0836_CT`). Calendar date is
computed in that zone, including DST. A row must actually issue and finish local
persistence within its registered window and before kickoff; its actual public
readback must precede kickoff. The registration must settle the exact source-age
limits and planned starting season/week before implementation/capture.

Earlier-day observations could have distinct registered `D1`–`D7` horizons.
They must not inflate primary sample size or replace a missed D0 observation.
No secondary horizons are registered by this draft. Compose the immutable capture
identity from registration, horizon, player, game, target and policy version.
Parameter-instance hashes identify actual fitted values without creating extra
independent football opportunities. A retry preserves the original opportunity;
an unqualified original cannot be replaced with a more favorable later row.

A separate version of the schema/capture/view contract is needed for this
identity. Do not retrofit horizon fields, model IDs, issue clocks or source hashes
into old records. The original receptions Weeks 7–14 registration and its earliest
eligible-common-triple rule remain separate. This draft does not register or
restart them or the RB protocol's six-hour window.

## Qualified scoring order

1. Load only already retained original scope witnesses. Prove exact local and
   committed bytes, policy, publication and local-completion clocks. Missing
   witnesses remain unavailable; new republication carries its real new clock.
2. Select registered opportunities and qualify both lab and website bindings
   before outcome access or website numeric rehydration. Zero eligible inputs
   must return coverage/reasons without opening outcomes. Preserve all planned
   opportunities, abstentions, missing comparators and late cases.
3. Freeze the selected input manifest. Then resolve attributable final outcomes
   under the registration's correction/participation contract. Unknown remains
   unknown. A supported appearance does not fill absent statistics with zero.
4. Score exact paired rows and separate all-player coverage from selected-line
   results. Declare the forecast product: mean, median/MAE point, actual predictive
   law or event probability. Current mean-only consumer validation cannot label a
   CDF median as a mean. Numeric points acquire no invented probability law.
5. Keep new qualified scorecards under a versioned record kind. Preserve old
   descriptive scorecards. Publication qualification supplies no automatic
   confirmation or promotion status; generic Week 8 classification is insufficient.

A scorer must not substitute today's source tree for the forecast's recorded
producer. Confirmation-driven method changes require a new version and later
evidence. Exposed 2022–2025 and 2026 Week 6 remain exposed. Existing category gates,
sample counts, planned analysis occasions and cross-season rules require their
original contracts; this draft changes none of them.

## Runtime and durable evidence

Retain the single scheduler/writer, strict 512 MiB shared physical quota and
200 MiB logical state cap, including temporary model peaks. Missed cadence grades
and replays without backfilling. A real hosted acceptance packet must pin source,
code, dependencies, budget, run/attempt IDs, clocks and reviewed export contents;
exercise restore/retry/idempotency, failure and actual scheduled delivery.

An exact state inventory alone cannot authorize uninspected future bytes. A
future unattended exporter needs a separately frozen content contract that
accepts only validated owned derived forecasts, permitted hash bindings and
corrections, while excluding raw feeds, queries, source bodies and private
weights. It must produce the exact reviewed file map, not a wildcard. Public
scope witnesses are metadata about that approved map, not a substitute review.

Private model/source/query retention across ephemeral hosted runners still needs
an actual permitted durable route. No new key, account, spending or external
upload is authorized by this draft. Implement and demonstrate the concrete
export/recovery boundaries before presenting an owner-only storage decision.
Continue independent research and supported capture/grading while that dependency
is unresolved; do not describe missing artifacts as reproducible replay.

## Weekly learning boundary

The existing weekly reference probe does not supply daily inference parameters.
Reusing trained weekly challengers later would need a separately versioned
inductive artifact contract: fixed training/source/cutoff/preprocessing/model
hashes plus each new query's own schema, source, cutoff and prediction receipt.
Do not relax the existing exact-query replay contract. Freeze any adaptive
training/calibration rule and finite budgets before its confirmation stream;
learning from earlier data under that rule differs from tuning after seeing
confirmation scores. No adaptive candidate is established by this design.
