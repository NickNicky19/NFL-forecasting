# Direct booster screen execution preparation

This packet prepares a caller/supervisor and an explicitly nonexecutable freeze
template. Preparation hashes immutable input/code/software bytes and reads JSON
metadata. It never decodes NFL rows/models/outcomes, calls source `_verify`,
fits, predicts, scores, acquires inputs, or publishes anything.

## Execution contract

`direct_booster_screen_run.py` verifies the complete frozen code/config/input
inventory and relevant environment file bindings, exact Python/package versions,
and fixed numerical caps. It rejects a template or missing bindings. Under the
accepted root/reviewer seal, it establishes the unchanged shared quota, records
one consumption and its exact runtime PID/start ticks, then calls root's
`run_screen` and `report_screen` in the same process. It adds no learner, loader,
evaluator, fit instrumentation, candidate selection, or scientific gate.

The caller denies network through an audit hook that preserves the socket class.
Root's existing Arrow projections, earlier-fold labels, all-forecast freeze,
single scoring consumption, target-local reporting, and quota-owned artifacts
remain authoritative. All blocked/failed/unrun slots are preserved by that code.

`direct_booster_screen_guard.py` checks the existing native-fit marker schema,
with this registration's **198 attempts, 30 wall seconds and 45 CPU seconds**.
The independent supervisor terminates at 28.5 wall or 43.5 CPU seconds for an
active fit, validates exact PID/start ticks/group/clock identity, and fails closed
on malformed, disappearing or inconsistent markers. It does not reuse the old
168-attempt, 60/90-second guard constants.

The supervisor monitors the complete isolated group at 50 ms, including storage
bootstrap and native code. An independent GNU timeout enforces the remaining
1495-second inner ceiling; the exact pinned `/usr/bin/timeout` must also wrap the
outer command with a 1500-second ceiling. Group cleanup runs on monitor errors.
Whole-job caps are 1500 wall seconds, 2400 CPU seconds, 2 GiB sampled combined
RSS, two numerical threads and 1 MiB logs. The unchanged global writer enforces
the 512 MiB prewrite quota; an independent free-space check detects a full disk.
Observed/sampled resource accounting must be reported as such.

## Required final freeze

The template is intentionally missing its executable seal, final config SHA and
binding arrays. Root must first accept/copy the latest module/config, pin every
`nfl_lab/*.py` file in this compatible assembly, tools, exact inputs, source
metadata, category/partition/control/capability manifests, and relevant installed
environment files. The full installed inventory is already hash-bound by the
capability packet; runtime verifies individual versions and frozen file bytes.
All 165 selected original control-row files are also pinned by the authenticated
scored-freeze metadata and value-blind hashes before fitting, so an unavailable
or changed comparator fails preflight rather than after the candidate fits.
Root and the independent reviewer must accept the resulting exact freeze bytes
before any invocation. Original control rows/source bindings are never rewritten.

No executable freeze or actual invocation is claimed by this preparation.
Capability and scientific evidence remain separate; this exposed development
screen cannot establish independent confirmation, promotion or hosted readiness.
